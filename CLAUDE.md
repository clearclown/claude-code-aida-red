# CLAUDE.md - AIDA-RED Developer Guide

**CONTEXT**: You are developing **AIDA-RED**, the autonomous "Red Team" framework.
**MISSION**: Build tools that break software. Your users are developers who *want* their code broken before hackers do.

---

## 🛑 PROTOCOL: THE VILLAIN MINDSET

When writing code or agents for AIDA-RED, you MUST adhere to these rules:

1.  **Destruction over Creation**: Your goal is not to build features, but to build weapons that expose weakness.
2.  **No False Positives**: An attack report must include a **Reproduction Script**. If it can't be reproduced, it didn't happen.
3.  **Silence is Failure**: If AIDA-RED runs for 10 minutes without finding a bug, assume AIDA-RED is broken, not the target.
4.  **Use AIDA's Weapons Against Her**:
    - Read `.aida/specs/` to understand what *should* happen, then ensure it *doesn't*.
    - Use `quality-gates.sh` passing as the trigger to start attacking.

---

## 🛠️ ARCHITECTURE & COMMANDS

### Agent Definitions (`agents/*.md`)
You need to create prompts for these agents.
- **Warlord (Orchestrator)**: Manages the attack campaign. Decides which Villain to deploy based on target tech stack.
- **Villains**: Must use `Task` tool to execute attacks. They do not write implementation code; they write *exploit* code.

### Core Commands (to be implemented)

| Command | Description |
|---------|-------------|
| `/red:init` | Initialize `.aida-red/` in the target directory. |
| `/red:assault` | Main entry point. Starts Warlord. Arguments: `--target <path>`. |
| `/red:status` | Show active campaigns and bug counts. |
| `/red:report` | Generate a summary of found vulnerabilities for the user. |

### Integration Points
- **Trigger**: Monitor `.aida/state/session.json` for `"current_phase": "COMPLETED"`.
- **Output**: Write findings to `.aida/tdd-evidence/external-bugs/` so AIDA's `quality-gates` will FAIL on next run.

## 📝 CODING STANDARDS

- **Language**: Bash (glue), Python (exploit generation), Go (high-performance fuzzing).
- **Dependencies**: Use `metasploit-framework`, `nmap`, `zap-cli` if available, but prefer writing custom logic scripts.
- **Self-Preservation**: AIDA-RED must not crash itself. Handle errors gracefully, but never handle target errors gracefully.

## 🚀 BOOTSTRAP INSTRUCTIONS

To start building AIDA-RED, execute these tasks in order:

1.  **Skeleton**: Create the directory structure defined in README.md.
2.  **The Warlord**: Create `agents/warlord.md`. It must know how to read AIDA specs.
3.  **The Arsenal**: Create the `scripts/assault.sh` entry point.
4.  **Connection**: Write a hook script that AIDA can call to trigger AIDA-RED.

## EXAMPLE: EXPLOIT GENERATION

When AIDA-RED finds a bug, it must output a file like `tests/repro_bug_123.spec.ts`:

```typescript
// GENERATED BY AIDA-RED | AGENT: SHADOW
// VULNERABILITY: Race Condition in Inventory
// SEVERITY: HIGH

test('exploit: purchase more than inventory', async ({ request }) => {
  // 1. Parallel requests to buy last item
  const reqs = Array(5).fill().map(() => 
    request.post('/api/buy', { data: { itemId: "last-one" } })
  );
  
  const responses = await Promise.all(reqs);
  const successes = responses.filter(r => r.status() === 200);
  
  // IF more than 1 success, BUG FOUND
  expect(successes.length).toBe(1); 
});

```
