# /red:report - Generate Vulnerability Report

Generate a comprehensive report of all vulnerabilities found during AIDA-RED campaigns.

## Usage

```
/red:report [--format <type>] [--campaign <id>] [--severity <level>] [--output <path>]
```

## Arguments

| Argument | Description | Default |
|----------|-------------|---------|
| `--format` | Output format: markdown, json, html | markdown |
| `--campaign` | Specific campaign ID | all |
| `--severity` | Filter by severity: critical, high, medium, low | all |
| `--output` | Output file path | stdout |

---

## Execution

### Step 1: Gather Findings

Collect all reproduction scripts and their metadata:

```bash
# Find all findings

## Findings

### [CRITICAL] VUL-001: Race Condition in Inventory

**Agent**: Joker
**Endpoint**: `POST /api/purchase`
**CWE**: CWE-362 (Concurrent Execution using Shared Resource)

#### Description

Concurrent purchase requests can exceed available inventory due to lack of proper locking.

#### Reproduction

```typescript
test('exploit: purchase more than inventory', async ({ request }) => {
  const reqs = Array(5).fill().map(() =>
    request.post('/api/buy', { data: { itemId: "last-one" } })
  );

  const responses = await Promise.all(reqs);
  const successes = responses.filter(r => r.status() === 200);

  // BUG: More than 1 success
  expect(successes.length).toBe(1);
});
```

#### Remediation

Implement optimistic locking or use database transactions with row-level locks.

---

### [HIGH] VUL-002: IDOR in User Profile

**Agent**: Shadow
**Endpoint**: `GET /api/users/:id`
**CWE**: CWE-639 (Authorization Bypass Through User-Controlled Key)

#### Description

Users can access other users' profiles by manipulating the user ID parameter.

#### Reproduction

```typescript
test('exploit: access other user profile', async ({ request }) => {
  const tokenA = await login('userA', 'passwordA');

  const response = await request.get('/api/users/userB-id', {
    headers: { Authorization: `Bearer ${tokenA}` }
  });

  // BUG: Returns 200 instead of 403
  expect(response.status()).toBe(403);
});
```

#### Remediation

Verify that the authenticated user owns the requested resource before returning data.
